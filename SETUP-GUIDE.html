Follow steps 1–10 in order, from a free Supabase account to a live app on Vercel with Google sign-in. Tick each step as you finish it; progress is saved in this browser. The second half explains how the platform works, for your defense.

Which path are you on?

🆕 Brand-new Supabase project

Do every step. In step 2, run only setup.sql.

♻️ Your existing project (already has tables)

In step 2, don't run setup.sql again (it fails with "type user_role already exists"). Run the upgrade files instead. Your data is kept.

Step 1 · Create the Supabase project

  1. Go to supabase.com/dashboard → New project. Name it dorsu-it-quest, set a strong database password (save it), and choose region Southeast Asia (Singapore).
  2. When it's ready, open Project Settings → API (or the Connect button) and copy the Project URL and the anon / publishable key. You need them in steps 5 and 8.
Never use the service_role / secret key in this app. Only the anon (publishable) key; Row Level Security does the protection.

Step 2 · Create the database

Supabase → SQL Editor → New query → paste the whole file → Run. Use a new query tab for each file.

🆕 New project

  1. Run supabase/setup.sql. It creates all tables, security rules and functions, and loads the curriculum: 4 subjects, 24 quests, 198 questions, 17 badges, plus staff tools, check-ins and 19 exclusive cosmetics.

♻️ Existing project: run these instead, in this order

  1. supabase/fix-permissions.sql: only if the app shows "permission denied for table…". Safe to run anyway.
  2. supabase/upgrade-staff-tools.sql: Command Center, Admin HQ, Briefings, expert-validation rubric.
  3. supabase/upgrade-daily-checkin.sql: Daily check-in, Daily Byte, exclusive titles and frames.
A warning pops up ("Potential issue detected… without Row Level Security")? Choose "Run without RLS". The scripts already turn RLS on for every table. Supabase's own "enable RLS" option adds a broken line (ALTER TABLE table…) that makes the run fail. Every file is safe to run more than once.

Check it worked (new query → Run):

select
  (select count(*) from public.subjects)  as subjects,   -- expect 4
  (select count(*) from public.questions) as questions,  -- expect 198 (more if you added some)
  (select count(*) from public.cosmetics) as cosmetics;  -- expect 19

Step 3 · Authentication settings

  1. Authentication → Sign In / Providers → Email: keep Email enabled. For the classroom pilot and the defense, turn off "Confirm email" so students can play right after signing up. (Supabase's built-in mailer sends only a few emails per hour.)
  2. Authentication → URL Configuration: set Site URL to http://localhost:3000 for now (you change it to your Vercel URL in step 9). Under Redirect URLs add: 
    http://localhost:3000/auth/callback

Step 4 · Google sign-in ("Continue with Google")

You make a pair of keys in Google Cloud and paste them into Supabase. It takes about 10 minutes. Keep two tabs open: Google Cloud and Supabase.

4a. Get the callback URL from Supabase

  1. Supabase → Authentication → Sign In / Providers → Google. Copy the Callback URL (for OAuth) shown there. It looks like: 
    https://YOUR-PROJECT-REF.supabase.co/auth/v1/callback
    Leave this page open; you'll come back to paste the keys.

4b. Create the Google keys

  1. Open console.cloud.google.com with your Gmail. Use the project picker at the top → New project → name it DOrSU IT Quest → Create, then select it.
  2. Go to APIs & Services → OAuth consent screen (in newer consoles: Google Auth Platform) → Get started:
    • App name: DOrSU IT Quest · User support email: your Gmail
    • Audience: External (so students' Gmail accounts can sign in)
    • Contact email: your Gmail → agree → Create
    Skip uploading a logo for now. A logo can trigger Google's brand verification, which takes days.
  3. Audience page: the app starts in Testing, where only the Gmail accounts you list under Test users can sign in (up to 100). Add your own Gmail and your panel's. For the real pilot, click Publish app so any Gmail account works. This app only asks for basic profile and email access, so Google's review shouldn't be needed.
  4. Clients (or Credentials → Create credentials → OAuth client ID):
    • Application type: Web application · Name: IT Quest web
    • Authorized JavaScript origins: add http://localhost:3000 (you add the Vercel URL in step 9)
    • Authorized redirect URIs: paste the Supabase callback URL from 4a. Not localhost and not /auth/callback; it must be the …supabase.co/auth/v1/callback one.
    Click Create and copy the Client ID and Client secret.

4c. Turn it on in Supabase

  1. Back in Supabase → Providers → Google: switch Enable Sign in with Google on, paste the Client ID and Client Secret → Save.
How the app handles Google players: a first Google sign-in creates the player account automatically, using the name from Google. On the Register page the Google button stays locked until the study's consent box is ticked (RA 10173). New Google players are then asked to add their year level and section on their Profile. If someone signs in with Google using an email that already has a password account, Supabase links the two.
Keep the Client secret private. It belongs only in Supabase. Never put it in the code, .env.example or GitHub.

Step 5 · Run it on your computer

npm install
copy .env.example .env.local      # Windows (Mac/Linux: cp .env.example .env.local)
npm run dev                       # open http://localhost:3000

Edit .env.local (not .env.example) and paste your values:

NEXT_PUBLIC_SUPABASE_URL=https://YOUR-PROJECT-REF.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=your-anon-or-publishable-key
NEXT_PUBLIC_SITE_URL=http://localhost:3000
  1. After editing .env.local, restart npm run dev (Ctrl+C, then run it again). The file is read only at startup.
  2. Open /register → tick consent → Sign up with Google → pick your Gmail. You should land on your Profile with a "finish your player profile" message.
.env.local is git-ignored, so your keys never go to GitHub. .env.example is pushed, so it must keep the placeholder values only. If the first page load is slow on Windows: close heavy apps and games, and add the project folder to Windows Defender exclusions.

Step 6 · Create the first admin

Everyone starts as a student. Pick one option:

Option A: make your Google / existing account an admin

update public.profiles set role = 'admin'
where id = (select id from auth.users where email = 'yourname@gmail.com');

Option B: create a separate admin login with SQL

Open supabase/create-admin.sql, change the 3 values in EDIT ME (email, password with 4+ characters, name), paste it into the SQL Editor and Run. If the email already exists, it just promotes that account. Don't save a real password into the file before pushing to GitHub.

  1. Log out and back in. Admins land on Admin HQ and the sidebar shows Admin and Command sections. Promote other faculty from Admin → Users & roles; no more SQL needed.

Step 7 · Push the code to GitHub

Create an empty repository on GitHub (no README), then in the project folder:

git init
git add .
git commit -m "DOrSU IT Quest"
git branch -M main
git remote add origin https://github.com/YOUR-USERNAME/dorsu-it-quest.git
git push -u origin main
Before pushing, check git status: .env.local, node_modules and .next must not be listed. They're already in .gitignore.

Step 8 · Deploy on Vercel

  1. vercel.com/new → Import your repo. Framework: Next.js (auto-detected); leave the build settings as they are.
  2. Environment Variables (Production and Preview):
    NameValue
    NEXT_PUBLIC_SUPABASE_URLyour Project URL
    NEXT_PUBLIC_SUPABASE_ANON_KEYyour anon / publishable key
    NEXT_PUBLIC_SITE_URLyour Vercel URL, e.g. https://dorsu-it-quest.vercel.app (no trailing slash)
  3. Click Deploy. If you didn't know the URL beforehand, set NEXT_PUBLIC_SITE_URL now and use Deployments → ⋯ → Redeploy. Environment changes only apply to new deployments.
The included vercel.json runs the app in Vercel's Singapore region, next to your Supabase database, so every page loads faster.

Step 9 · Connect the live URL (Supabase + Google)

Without this, logins on the live site send people back to localhost or show a redirect error.

  1. Supabase → Authentication → URL Configuration: set Site URL to https://YOUR-APP.vercel.app. Under Redirect URLs keep localhost and add: 
    https://YOUR-APP.vercel.app/auth/callback
  2. Google Cloud → your OAuth client → Authorized JavaScript origins: add https://YOUR-APP.vercel.app → Save. The redirect URI stays the Supabase one; don't change it.

Step 10 · Final check on the live site

  1. The landing page loads with no "Setup needed" banner, and the animations play. If not, click the ✨ Effects switch → Full.
  2. Sign up with Google works with a second Gmail (a test user, or any Gmail once published).
  3. As a student: claim the Daily check-in, answer the Daily Byte, play a quest (3-2-1-GO → Victory screen).
  4. As admin: Admin HQ shows numbers. Create a class, have the student join with the code, then check the Command Center watchlist and radar.
  5. On a phone: open the site → Install app (Android/Chrome) or Share → Add to Home Screen (iPhone).

Daily check-in & exclusives

  • Supply Drop, a 7-day track: +10, 15, 20, 25, 30, 40, then Day 7: +75 XP and a Supply Crate with a random exclusive. Missing a day never resets the track, because the study notes students have limited connectivity.
  • Daily Byte: one question from your weakest subject. A correct answer doubles that day's XP; one try. Only the Byte counts toward the learning streak, so attendance stays tied to practice.
  • Exclusives: 19 titles and animated emblem frames in 4 rarities. Unlocked at 3/7/14/30/60 check-ins, 10/25 correct Bytes, or from crates. Equip them in the Locker.
  • Instructors see "checked in today" for their students. Students see only their own attendance.

Quest Forge (game creator)

  • Pick a subject and game mode (Quiz, Simulation, Boss fight, Pretest, Posttest); set difficulty, XP and timer with sliders.
  • Add questions from 6 types (multiple choice, true/false, select-all, short answer, code trace, ordering). Click to mark correct answers; reorder, duplicate or delete them.
  • A live phone preview plays the selected question. Mission check lists problems before saving. Ctrl+S saves.
  • Expert validation: faculty rate each quest 1–5 on accuracy, alignment, difficulty fit and technical quality. Shows weighted means with Excellent / Very good / Good ratings (Objective 3).

Security & privacy (RA 10173)

  • Row Level Security on every table: students see only their own data, instructors only their own classes, admins everything.
  • Answer keys are readable only by staff. Grading, XP, check-ins and cosmetics are all computed by the database. 33 automated tests cover forging attempts.
  • Consent checkbox for both email and Google sign-up. Anonymous ITQ-XXXXXX codes in exports. Leaderboard alias and opt-out.
  • The Google client secret lives only in Supabase. The app uses only the public anon key.
  • Signed-in pages are never cached on shared lab PCs. Security headers are on. CSV exports are protected against formula injection.

Effects switch & PWA

Windows or phones set to "reduce motion" or "best performance" turn animations down automatically. The ✨ Effects button (landing page top bar, app sidebar) switches between Auto, Full and Off. The app is installable on Android, iOS, Windows and macOS, and shows an offline page when Wi-Fi drops.
